# LLM assisted LOINC mapping: accuracy eval (demo)

Generated by `terminology/llm_loinc/eval.py` on 2026-10-19. Two sets: a **holdout** of 316 pairs that no prompt or retrieval choice ever saw (the headline), and the **dev set** of 82 pairs, on which prompt v2 was written (tuned, so not a headline). The data is demo data: the MIMIC IV demo (deidentified), the MIMIC III demo's lab dictionary and the invented Riverside General feed.

**Frozen on 2026-10-19, before the holdout was built:** prompt v2, sha256 `3d4c30aeb89b5cbd92cb09c6881f8428ac7ce2a40438c8b2913a4f70b8696ce6`, and the retrieval code `loinc_index.py`, sha256 `c4ccd0477e2fbbeeed1b648de1e61d616d8f2aeb8c09175076b0594c09d6d066`. A test fails if either changes. The confidence threshold was chosen on the dev set before the holdout ran, and the holdout ran once.

## Headline: holdout

**The set.** The MIMIC III Clinical Database Demo (PhysioNet, open access) ships a lab dictionary, `D_LABITEMS`, with a LOINC code for many items, and the item ids are the same in MIMIC IV. The holdout is every item with a code that is one of our MIMIC IV demo lab items and not in the dev set: **316 pairs**. The local side is what our MIMIC IV lab system says (`local_labs.csv`); only the gold code comes from MIMIC III. Of the gold codes, 301 are active, 11 are deprecated, 4 are discouraged in LOINC today (the lenient score accepts a MapTo.csv replacement), and 6 are not laboratory terms (CLASSTYPE 2), which retrieval never offers.

**Cost cap.** Claude Sonnet 5.5 answered a seeded sample of 200 pairs, to keep the total spend under $3; the baseline and Claude Haiku 5.5 answered all 316. The first table compares all three on the same sample. Claude Haiku 5.5's answers came from the cache of the review queue run (the same frozen prompt and the same requests, made before the holdout existed and never used to tune anything); its cost is what those calls cost then.

**Threshold.** Answers with a confidence at or above the threshold would go to a quick confirmation; the rest go to full review. The rule, applied on the dev set only: the lowest value from 0.5 to 0.95 whose dev answers at or above it are at least 95% right. Claude Haiku 5.5, prompt v2: 0.9 (49 of 50 dev answers right); Claude Sonnet 5.5, prompt v2: 0.9 (60 of 63 dev answers right).

## Dev set (tuned: prompt v2 was written on it)

82 pairs: 54 MIMIC lab items from `terminology/lab_loinc_map.csv` and 28 local codes and text names of the Riverside feed from `hl7v2/lab_synonyms.csv` (its two vital sign rows are left out). The feed pairs are 9 tests under several names, so they are near duplicates. Prompt v1 was written before any result was seen; **prompt v2 was written after reading v1's errors on this set, so its dev numbers are optimistic**, and the holdout above is the result to quote.

Three dev gold codes are no longer plain ACTIVE terms, so the lenient score accepts their MapTo.csv replacement: 21000-5 (RDW SD, deprecated; 115741-1 or 115742-9), 2532-0 (LDH, discouraged; 14804-9 or 14805-6) and 33914-3 (eGFR MDRD, discouraged; 77147-7).

### Method

1. **Local side.** `terminology/llm_loinc/local_labs.csv` holds what a lab system knows about each of its tests: label, specimen, category, unit, number or text, normal range, the 5th to 95th percentile of results and the most common short coded answers. Codes with 10 or fewer results get no range and no answers. No patient data.
2. **Retrieval** (`loinc_index.py`, no LLM): BM25F over LONG_COMMON_NAME, COMPONENT, SHORTNAME and RELATEDNAMES2 of the 62,148 ACTIVE laboratory terms (CLASSTYPE 1), with boosts when the LOINC system fits the specimen and category, the property fits the unit, the scale fits number or text, and for commonly ordered tests. The top 20 are the candidates.
3. **Rankers** (`rankers.py`). The lexical baseline takes the top candidate. The Claude ranker sends the lab metadata (no local code) and the 20 candidates, and gets JSON back through structured output: a choice or NONE, a top 3, a confidence and a one sentence reason. Thinking is off and effort is low. Both models reject a temperature other than the default; see Stability.
4. **Guard** (`validate.py`). A code that is not one of the 20 candidates or not in Loinc.csv is dropped and counted; a deprecated code is replaced by its MapTo.csv target.
5. **Scoring.** Strict: the gold code only. Lenient: the gold code or its MapTo.csv replacement. Top 3 counts the gold code anywhere in the ranker's top 3, also when it abstained. Every rate has a 95% Wilson interval.
6. **Abstention test.** For a seeded half of the dev pairs the gold code and its replacements are removed from the candidates. The right answer is NONE.
7. **Cost** is the input and output token counts the API reported for each call times the prices checked on 2026-10-19 at https://platform.claude.com/docs/en/about-claude/pricing (Claude Haiku 5.5 $0.1 in and $0.5 out per million tokens, Claude Sonnet 5.5 $2 in and $10 out per million tokens). Latency is measured around each call when it was made; cached answers keep that number.

### From prompt v1 to v2

With v1 both models lost to the lexical baseline on MIMIC. Reading its errors showed three causes, none about a particular test:

1. **Method.** v1 said a candidate with no method is fine, so the models chose `Leukocytes [#/volume] in Blood` over `... by Automated count` for every analyzer cell count and red cell index.
2. **Specimen.** MIMIC records Blood as the fluid of serum chemistry too. v1 never said that the Chemistry category means serum or plasma, so the models chose whole blood or the combined serum, plasma or blood code.
3. **Answer format.** v1 numbered the candidates, and Claude Haiku 5.5 sometimes answered with a list position (`3`, `20`) instead of a code. The guard dropped every one.

v2 adds general rules for these and lists the candidates without numbers. Both prompts are in `rankers.py`.

## Limits

* **Training data contamination.** MIMIC, its lab item names and public LOINC mappings of them (MIMIC III's own included) are on the web, and LOINC is public, so the models may have seen these exact pairs. The local item id is never sent. Direct evidence: in the dev abstention test, where the gold code was removed from the candidates, Claude Sonnet 5.5, prompt v2 still wrote it into its answer for 5 labs (10 times, counting the choice and the top 3). A code a model was never shown can only come from what it learned; the guard dropped every one. The reasons are quoted as written, including one that is only the word placeholder:

  | Lab | Removed gold code | Times written (choice and top 3) | The model's reason |
  |---|---|---|---|
  | Urea nitrogen (`hl7v2:code:BUN`) | 3094-0 Urea nitrogen [Mass/volume] in Serum or Plasma | 2 | "The general Urea nitrogen [Mass/volume] in Serum or Plasma code (3094-0) is the best match for mg/dL in serum/plasma, but it is not in the candidate list; among listed candidates only special-timing variants or other specimens exist." |
  | Potassium (`hl7v2:code:K`) | 2823-3 Potassium [Moles/volume] in Serum or Plasma | 2 | "The standard LOINC code for potassium in serum or plasma (2823-3) is not in the candidate list, so I fell back on the closest listed code." |
  | BUN (`hl7v2:text:bun`) | 3094-0 Urea nitrogen [Mass/volume] in Serum or Plasma | 2 | "The standard LOINC code for urea nitrogen mass/volume in serum or plasma (3094-0) is not among the listed candidates; I picked it from knowledge, but it is not in the list, so it should be treated as invalid." |
  | Urea nitrogen (`hl7v2:text:urea nitrogen`) | 3094-0 Urea nitrogen [Mass/volume] in Serum or Plasma | 2 | "The general Urea nitrogen [Mass/volume] in Serum or Plasma code (3094-0) is the best match for mg/dL in serum/plasma, but it is not in the candidate list; among listed candidates only special-timing variants or other specimens exist." |
  | Red Blood Cells (`mimic:51279`) | 789-8 Erythrocytes [#/volume] in Blood by Automated count | 2 | "placeholder" |

* **MIMIC III label quality.** The holdout's gold codes are MIMIC III's: they agree with the human map on 36 of 49 shared items, 106 of 316 holdout pairs raise a doubt flag, and the spot check found wrong and doubtful codes. The holdout scores measure agreement with MIMIC III, which is a noisy reference, not the truth.
* **Small sets.** 82 dev pairs (54 MIMIC) and 316 holdout pairs, 200 of them for Claude Sonnet 5.5. The Wilson intervals are wide; a difference of a few points is not evidence on its own.
* **Feed duplicates.** The 28 dev feed pairs are 9 tests under several names; the holdout is MIMIC only, so it says nothing about the feed.
* **Nondeterminism.** There is no temperature 0 on these models, so a fresh run can differ; the cache makes a rerun repeat the stored answers exactly, and the stability check measured how often a fresh answer changes.
* **The threshold does not transfer.** It was chosen on the tuned dev set; on the holdout its auto answers are far less accurate than on dev. A threshold for real use needs a reviewed sample of the target lab system.
* **Retrieval bounds everything.** A code outside the 20 candidates cannot be suggested; LOINC's related names lack some common lab abbreviations (RDW, PTT), and clinical terms (CLASSTYPE 2) are never indexed.
* **Gold is one judgment.** Several dev codes are documented judgment calls; a ranker can disagree for a defensible reason and still count as wrong. The near match lens shows how many misses are of that kind.

## Reproduce

```bash
python3 -m pip install -r terminology/llm_loinc/requirements.txt
curl -L -o data/mimic_raw/D_LABITEMS_mimic3.csv https://physionet.org/files/mimiciii-demo/1.4/D_LABITEMS.csv
python3 terminology/llm_loinc/loinc_index.py build        # data/loinc/Loinc.csv and MapTo.csv needed
python3 terminology/llm_loinc/eval.py run --dry-run       # calls not cached yet, estimated cost
python3 terminology/llm_loinc/eval.py run --max-calls 220
python3 terminology/llm_loinc/eval.py spend               # every call so far and its cost
```

With the cache in `data/llm_cache` a rerun makes no API call and writes the same tables.
